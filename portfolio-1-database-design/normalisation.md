# Normalisation of the CityLib Database

The CityLib database is split into nine tables so that each piece of information is stored only once. For example, the category name "Fiction" is kept in the `categories` table, and each book only stores a `category_id` that points to it. If a category is renamed, only one row needs to change instead of every book in that category. The same idea is used elsewhere: `book_authors` exists because one book can have several authors and one author can write several books, `book_copies` separates a title from the physical copies that can be borrowed, and `loans` stores member and staff IDs instead of repeating their names and emails. Because every column depends only on the key of its own table, the design meets Third Normal Form (3NF) and avoids repeated data and update mistakes.
